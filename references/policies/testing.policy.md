# 测试规范（Testing）

## 测试作为 Definition of Done 的一部分

代码 + 测试 + 全部质量门禁 + CHANGELOG + 文档同步，缺一不算完成。

## 执行

- 用 AGENTS.md Development Commands 的测试命令（裸命令）
- 新增功能/修复必须补对应测试
- 改动公共接口/核心逻辑 → 运行相关测试套件
- 测试结果必须记录**真实输出**：通过数量、失败项、命令与退出码

## 测试类型

- 单元测试：核心逻辑
- 集成测试：模块间/外部依赖
- 按项目实际能力逐步补充，不虚构不存在的测试框架

## 质量门禁（AGENTS.md Development Commands）

- 格式检查
- 静态检查（Lint）
- 类型检查（如适用）
- 构建

## 禁止

- 声称"测试通过"而无输出证据
- 跳过失败测试或注掉断言来"通过"
- 新增代码不写测试就宣称完成

## 测试保护（Test Protection）

删除或降级测试必须说明：
- 为什么删除
- 是否有替代测试
- 是否降低覆盖率（降低 → 需用户确认）

禁止仅因"测试过时"直接删除测试；过时测试先更新，再评估保留/删除。删除核心模块测试视同 Breaking Change，需走 AGENTS.md 的删除保护流程。

## 测试活性（Test Activity）

**证据等级：人工背书。** 本节是判断标准，没有脚本自动检测——写在这里不等于已被机械强制。

**空洞测试定义**：移除被测功能后测试仍然通过 = 该测试没有覆盖那个功能。断言必须针对**完整的目标集合**，而不是其中一个子集——只断言"清单里包含 A"的测试，在清单丢掉 B、C 时照样绿。

**按对象分级要求**（避免把变异测试变成新的形式主义）：

| 测试对象 | 要求 |
| --- | --- |
| 门禁、守卫、枚举清单、注册表、关键路径 | **必须**提供负向 fixture 或变异证据：构造一个真该失败的输入并确认测试转红；或临时移除被测分支并确认测试转红 |
| 一般业务逻辑测试 | 不强制逐个做删除变异；正常的正例 + 边界 + 异常覆盖即可 |

**事实源规定（"完整集合"从哪来）**：断言"完整集合"之前必须先确定该集合的**事实源**，不得凭印象判定"这应该就是全部"。事实源是项目里那份**声明**该集合的文件，例如：

- 治理工件清单 → `.governance/manifest.json`
- 受保护文件清单 → `docs/rules/` 下的治理文件保护规则
- 同步组清单 → `.governance/sync-rules.json`
- 门禁清单 → AGENTS.md 的 Development Commands / 验证序列
- CI 作业清单 → CI 配置文件本身

对照方式：**声明集合**（取自事实源）逐项对比**机制集合**（脚本实际扫描的目录、实际注册的测试、实际运行的 CI 作业）。两者不相等即为缺陷（见 `docs/rules/lifecycle.md` § 声明与机制的差距）。断言里应当直接引用事实源，使事实源新增条目时测试自动失败，而不是把清单在测试里抄一份。
