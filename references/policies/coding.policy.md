# 编码规范（Coding）

## 语言与风格

- 遵循项目既有代码风格与格式化配置（Formatter/Lint 配置为基准，不自定义风格）
- 命名：按语言惯例（camelCase / snake_case / PascalCase），保持一致
- 保持向后兼容；不因重构热情破坏公共接口
- **行尾由仓库声明，不靠每台机器的 Git 配置**：仓库根应提供 `.gitattributes`（`* text=auto eol=lf`，`*.sh` 强制 LF，二进制后缀标 `binary`）。理由是 `core.autocrlf` 是**本机**设置——一台配置不同的机器就能提交 CRLF blob，使之后每次 diff 变成整文件改动。没有 Formatter/Lint 配置的项目（如纯脚本仓库）也应至少有这一条，因为它约束的是仓库存储而非编辑器行为。**注意**：INIT 当前不生成 `.gitattributes`，项目需自行添加；上面括号内的三条即完整内容，无需另找范本。

## 结构与依赖

- 遵循 docs/ARCHITECTURE.md 声明的目录结构，不随意改变
- 新模块/服务必须登记到组件登记表（New Code Registration）
- 加依赖必须用项目包管理器并说明用途；重型依赖需用户确认
- 不引入"看起来不错"但未被要求的抽象

## 工程克制与机制测试（Engineering Restraint / Machinery Test）

**机制测试**：新增任何非平凡之物（代码、抽象、接口、包、状态、配置、依赖包装、恢复路径、测试钩子、文档、计划、门禁、矩阵、审查步骤、流程）前自问——"若它今天不存在，当前需求是否仍会独立证明其必要？" 否 → 不加；是 → 用最窄的既有所有者或成熟机制解决；直接实现够用就不插入框架或流程。**流程也是机制**：计划、门禁、矩阵、审查阶段、检查清单、证据工件与抽象、状态、恢复系统同等举证。

- 直接完整实现已批准能力，不以"简单"之名削减真实需求。
- 优先既有语义所有者、既有原语、标准/Node/OS 能力、成熟库，其次才自建机制。
- 偏好有界真实失败而非投机韧性；罕见或假设的失败允许响亮失败，不建"恢复的恢复"。
- 测试保护有意义契约与观察到的风险，不因可测性制造生产 DI、工厂、钩子、状态或恢复分支。
- 证据证明具体主张，不为纪念单次事故建立永久门禁或回归仪式。
- 既有代码无自动保留特权，也不得因"理论上更小的设计存在"而无因翻动。
- 语义/所有权/提供方/状态/失败决策未决时升级，不藏在通用抽象、配置系统或框架后。
- 授权行为与证明完成后停止，不自动追加清理、加固、稳定化、审查或收尾轮次。

**边界一：已批准需求优先。** 本规则约束未经批准的新增机制，不否决用户已批准的功能、架构决策、迁移要求、门禁要求或 TASK 计划；若批准方案与工程克制冲突，必须升级决策，不得自行删减需求。

**边界二：语义接缝合法。** 允许为当前需求保留清晰的接口边界、模块边界、扩展点和稳定语义；禁止为尚不存在的消费者实现完整抽象层、配置系统、插件机制、恢复链、通用框架或状态机。

## 修改已有代码

执行 Code Modification / Deletion Protection 四步：Context Analysis → Determine Code Ownership → Before Deletion → Breaking Changes（见 AGENTS.md 与 lifecycle.md）。

## 变更归位与残留清理

该规则不只适用于删除，也适用于重命名、移动、替换、弃用、拆分/合并、关闭 feature flag，以及 API、CLI、协议、数据格式、配置、模板、生成物和翻译变更。修改前维护 Change Hygiene Ledger：记录旧项/新项、影响表面、处理决定、允许保留的兼容引用、责任人、退出版本/日期和证据。

- 当前规范/实现层只保留现行名称和行为；不得用“已删除”“不再支持”或“这里曾经……”等否定式注脚代替清理。
- 兼容/迁移层可以保留旧名称、别名、shim 或 adapter，但必须明确用途、范围、责任人、退出条件和测试；历史层（CHANGELOG、ADR、归档）可以记录旧事实和原因。
- 先用 `rg` 搜索代码、配置、文档、测试、CI、模板、生成物、链接、锚点、动态字符串、插件注册、manifest 和环境变量，再按“单一事实源 → 引用 → 投影”顺序修改。未分类命中或未知消费者不得假设不存在。
- 删除公共接口或改变权限、安全、校验、协议、数据格式时，必须有调用方盘点、迁移/回滚方案和必要的审查/用户确认；不得以清理为由降低安全门槛或静默制造破坏性变更。

## 禁止

- 密钥/凭据硬编码
- 无关重构（scope creep）混入任务
- 删代码只因"看起来没用"（动态调用、插件、配置驱动代码需特别谨慎）
- 不更新知识就改代码
