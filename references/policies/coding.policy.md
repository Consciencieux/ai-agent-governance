# 编码规范（Coding）

## 语言与风格

- 遵循项目既有代码风格与格式化配置（Formatter/Lint 配置为基准，不自定义风格）
- 命名：按语言惯例（camelCase / snake_case / PascalCase），保持一致
- 保持向后兼容；不因重构热情破坏公共接口

## 结构与依赖

- 遵循 docs/ARCHITECTURE.md 声明的目录结构，不随意改变
- 新模块/服务必须登记到组件登记表（New Code Registration）
- 加依赖必须用项目包管理器并说明用途；重型依赖需用户确认
- 不引入"看起来不错"但未被要求的抽象

## 修改已有代码

执行 Code Modification / Deletion Protection 四步：Context Analysis → Determine Code Ownership → Before Deletion → Breaking Changes（见 AGENTS.md 与 lifecycle.md）。

## 变更归位与残留清理

该规则不只适用于删除，也适用于重命名、移动、替换、弃用、拆分/合并、关闭 feature flag，以及 API、CLI、协议、数据格式、配置、模板、生成物和翻译变更。修改前维护 Change Hygiene Ledger：记录旧项/新项、影响表面、处理决定、允许保留的兼容引用、责任人、退出版本/日期和证据。

- 当前规范/实现层只保留现行名称和行为；不得用“已删除”“不再支持”或“这里曾经……”等否定式注脚代替清理。
- 兼容/迁移层可以保留旧名称、别名、shim 或 adapter，但必须明确用途、范围、责任人、退出条件和测试；历史层（CHANGELOG、ADR、归档）可以记录旧事实和原因。
- 先用 `rg` 搜索代码、配置、文档、测试、CI、模板、生成物、链接、锚点、动态字符串、插件注册、manifest 和环境变量，再按“单一事实源 → 引用 → 投影”顺序修改。未分类命中或未知消费者不得假设不存在。
- 删除公共接口或改变权限、安全、校验、协议、数据格式时，必须有调用方盘点、迁移/回滚方案和必要的审查/用户确认；不得以清理为由降低安全门槛或静默制造破坏性变更。

## 禁止

- 密钥/凭据硬编码
- 无关重构（scope creep）混入任务
- 删代码只因"看起来没用"（动态调用、插件、配置驱动代码需特别谨慎）
- 不更新知识就改代码
