# 元数据原则

## Hard Rules（L1）

1. **封闭 schema** — 每种文档类型的 frontmatter / 元数据字段集合封闭；未知字段视为缺陷。
2. **禁止膨胀** — 不得为搜索、标签堆砌或「以后可能有用」任意加字段。
3. **禁止正文回填** — 正文已有的信息不得再复制进元数据。
4. **演进须决策** — 新增或删除字段须经 ADR（或项目等价决策记录）；禁止静默改 schema。
5. **状态单一权威** — 生命周期状态以约定的单一位置为准（通常 frontmatter）；禁止正文再维护第二份 Status 块与之并行。

## Recommended Patterns（L2）

- 字段最小化：身份、状态、代际/profile、目标域等真正被门禁或路由消费的键
- 机器消费的枚举值封闭，并与检查器/解析器同一事实源
- 翻译/投影文件的元数据不引入与 canonical 冲突的第二套状态

## Project Customization（L3）

- 具体键名、枚举拼写、是否 YAML/JSON frontmatter 由项目定
- 哪些类型需要哪些键由项目 ADR 定稿
- 本仓或任一参考实现的键名表**不是** L1
