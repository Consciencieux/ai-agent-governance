# 上下文与协作

## 工作记录

简单任务使用当前材料。跨轮、多问题或跨会话工作沿用项目计划、Issue 或记录；需要新文件时采用[任务片段](../assets/task-state.md)。保留目标、决定、当前工作、具体已知问题及文件位置，完成时核对本次范围。

来源数据与代码由原文件维护，记录保存定位与决定。用户提出新目标或限定范围时更新工作安排；新发现问题先归入本次、范围外或待输入，再继续原目标。

## 刷新事件

- 新任务：读取所选执行入口及适用材料。
- 新模块或操作：补读所需规则、相关代码与来源。
- 新会话或上下文压缩后：重读核心、当前入口、工作记录及适用规则，核对磁盘上的实际进度。
- 来源或规则变更：刷新变化文件及受影响的判断。

已完整读取且未变化的材料复用。交接提供目标、授权、版本、关键决定、结果位置和待办；接手后核对实际状态。

## 并行协作

按独立职责分配任务，明确接口和文件范围，使用宿主已有的协作或 worktree。共享可写资源确需互斥时使用实际原子锁及其释放机制，工作记录中的状态字段只记录进度。

提交前核对并行变化，保留他人工作。单 Agent 的普通任务直接工作，不创建额外锁或状态协议。
