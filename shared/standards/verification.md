# 验证

<a id="ver-01"></a>
## VER-01 验收行为

明确正确结果、关键约束和可观察的失败，依据变更选择验证。功能使用真实场景与关键边界，缺陷修复补能区分正确和错误行为的回归样例；已有测试充分覆盖时复用。

可以稳定复现时先观察原失败，再验证修复。间歇性或环境问题用日志、可控输入、隔离实验建立证据。TDD 按任务采用；单纯文案、注释与格式修改检查对应文本和格式即可。

<a id="ver-02"></a>
## VER-02 有效测试

断言针对实际契约。布尔 API 可以断言真值，文件生成可以断言文件存在；涉及内容、行为或完整集合的契约还要核对这些结果。关键行为被移除而测试照常通过时，补充能暴露该缺陷的断言。

拒绝输入、权限守卫和校验失败分支使用应被拒绝的样例；序列化用边界数据及往返结果，枚举和打包检查约定集合与可消费性。不要为本来接受全部合法输入的操作虚构失败分支。

复用公开边界与测试工具。删除旧契约对应的失效测试，保留当前行为的保护；禁止删除仍有效的失败断言来通过测试。测试结构可以随实现重组。

<a id="ver-03"></a>
## VER-03 范围与执行

先验证直接受影响的行为；公共基础设施、跨模块契约和广泛影响扩大到相关套件，发布遵循项目验证约定。相同版本、条件和产物已有有效结果时复用，变化后重验受影响部分。

测试发现、注册或路径变化后核对实际收集的用例；查看失败、跳过和零测试原因。已知稳定失败与本次新增失败分别定位。真实工具或数据缺口写明受影响的验证，继续可独立完成的工作。

<a id="ver-04"></a>
## VER-04 消费者与产物

改动安装、打包、生成关系或相关平台行为时，使用实际输出验证消费者路径：解包、加载入口与依赖，执行关键命令。资源定位、缓存或残留可能掩盖问题时使用干净目标；项目 CI 中同版本的有效结果可复用。

按实际分发和平台承诺选择样本；普通说明修改无需重复整套安装与平台矩阵。UI 或文档布局改动查看成品；性能结论使用一致条件的测量。

<a id="ver-05"></a>
## VER-05 结果交付

正常结果简要说明运行命令、通过情况和关键观察。详细输出保留在工具记录或项目现有日志中。失败指出实际原因、影响与下一步；只读核验和已执行修改分别描述。

禁止虚构执行、数量或成功状态，禁止吞掉错误后返回成功。验证服务于当前主张和交付，不追加与任务无关的证明材料。
