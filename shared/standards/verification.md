# 验证

<a id="ver-01"></a>
## VER-01 验收行为

在实现前确定正确结果、关键约束和可观察的失败。使用项目的测试、静态检查、构建和运行方式，依据受影响行为选择验证范围。

新增功能覆盖实际用法和关键错误路径；修复缺陷增加能区分正确与错误行为的回归用例。可以稳定复现时先观察原失败再验证修复；间歇性或环境相关问题采用可控输入、日志或隔离实验建立证据。

<a id="ver-02"></a>
## VER-02 有效测试

断言实际契约及完整目标集合。禁止只查文件存在、关键词出现或被测函数返回真值，就认定行为正确。移除关键行为后测试仍通过，说明断言没有保护该行为。

校验器、守卫、序列化、枚举和打包契约应有应当失败的输入，并确认它会失败。复用公开边界与现有测试工具；测试需要不能成为生产注入框架或测试专用开关的唯一理由。

删除失效测试时说明被删除的旧契约，并为当前行为保留测试；禁止把仍有效的失败断言删掉。测试文件本身可随正确架构重组。

<a id="ver-03"></a>
## VER-03 范围与实际执行

先运行直接相关的测试，公共基础设施、跨模块契约或广泛影响再扩大到有关套件。发布执行项目规定的完整验证。目录改名、注册和测试发现变更时，核对实际收集与执行的用例。

检查失败项、跳过项和零测试结果；测试工具存在却没有运行相关测试，应修正发现与执行路径。环境缺口说明缺少的工具、材料及影响的验证，继续完成可以独立验证的部分。

<a id="ver-04"></a>
## VER-04 真实产物

涉及安装、生成、发布或跨平台承诺时，在干净目标中使用实际输出：解包、读取入口、解析配置、加载运行时依赖并执行关键命令。验证消费者的完整路径，而非仅检查生产者目录。

UI 与文档布局需要查看实际成品；性能主张采用一致条件的测量。源码、生成物、文献或示例的存在分别按它们实际证明的内容判断。

<a id="ver-05"></a>
## VER-05 结果交付

记录实际运行的命令、退出结果及关键观察。正常结果简要报告，失败指出具体原因与影响；详细日志保留在工具输出或现有记录。

禁止编造通过数量、运行记录或成功声明，也禁止吞掉错误后按成功返回。测试、格式或构建失败应先定位属于本次变更、已有问题还是环境问题，再处置。
