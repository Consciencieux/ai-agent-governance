# 项目知识与表达

<a id="know-01"></a>
## KNOW-01 单一事实来源

同一事实有一个维护位置：配置存值，规范定行为，代码实现行为，数据保存观察。其他位置通过引用、复用或生成使用它。相同的字面值不一定是同一事实。

事实变化时先改负责人再更新依赖。文档和实现冲突，回到需求、约定与观察判断谁有误；禁止仅因某文件自称权威，就把当前错误传播到所有位置。

<a id="know-02"></a>
## KNOW-02 文档职责

入口保存项目用途、实际命令及关键路由；当前文档解释现行接口与用法；调研记录保存事实与来源；问题记录保存缺陷、证据和影响；设计记录保存非显然的决定与理由；计划保存待完成工作；历史记录保存已经发生的变化。沿用项目现有目录和语言约定。

禁止在多个入口复制完整规则，或将施工历史、内部评审和研究论证搬进当前操作说明。使用者文档直接说明如何使用，维护者材料记录如何开发与验证。

<a id="know-03"></a>
## KNOW-03 相关更新

改变公开行为、命令、配置、安装、接口或架构时，同步受影响文档；局部内部修复更新实际受影响的说明。变更日志按合并或发布边界记录用户可感知变化。仅为“做完流程”而新建 Feature Registry、ADR 或多份翻译，属于无关工作。

已有翻译、示例和生成文档按来源关系同步。尚未验证的内容留在当前工作记录，文档避免将目标写成已实现能力。实际进度与计划不符时更新当前决定和后续工作。

<a id="know-04"></a>
## KNOW-04 自然表达

用完整句子表达对象、动作、依据和结果。禁止空泛黑话、电报体、无理由加粗、逐行解释代码的注释，以及在完整结论后追加无信息的免责声明。

“这不是……而是……”“不意味着……”只有在改变当前判断时才提供信息；删除后事实、范围和理解无损的否定应删除。限制附在它真正影响的结论上。表格用于有统一行列语义的比较，长段论证使用正文。

<a id="know-05"></a>
## KNOW-05 可复用经验

将实际重复出现、能改变未来决定的经验写进已有责任文件，保留具体表现、适用条件与做法。一次任务的执行日志留在任务记录。规则、方法与测试分别保存判定、操作和可观察契约。
