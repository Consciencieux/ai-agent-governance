# 项目知识与表达

<a id="know-01"></a>
## KNOW-01 单一事实来源

为同一事实确定一个主维护位置，其他位置引用、复用、生成或按明确关系同步。相同字面值可能代表不同事实；配置、行为规范、实现和观察数据分别承担自身职责。

来源变化后更新相关用法、索引和生成物。文档与代码冲突时，回到需求、决定和实际运行判断错误一方，再修正依赖。导航优先链接来源；必要摘要保留读者需要的信息，高频变化的状态与数量尽量从来源取得。

<a id="know-02"></a>
## KNOW-02 文档职责

入口说明用途、命令与导航；当前文档解释现行行为；调研保存事实与来源；问题记录保存观察、复现和处置；设计记录保存决定与理由；计划保存工作安排；历史记录保存已发生变化。

一份文档可以包含支撑其主问题的背景、例子和后果。出现独立维护的长期主题时才拆分并引用。沿用项目目录、语言和元数据约定，按实际需要建立记录；禁止为分类完整生成整套目录、状态矩阵或登记表。

<a id="know-03"></a>
## KNOW-03 更新、索引与历史

公开行为、命令、配置、安装和架构变化时更新相关说明；内部修复只更新受影响的内容。已有翻译、示例与生成文档沿来源关系同步。计划状态或位置变化时同步实际引用，索引保留导航作用。

CHANGELOG 或 changeset 按项目准入和发布流程记录值得说明的变化；可使用项目既有的逐 PR 变更片段。禁止为了通过流程而每次修改都追加条目，或把测试日志、审批叙述和施工日记塞入发行说明。

发布历史保留当时事实；纠错注明缘由，不能用今天的设计改写过去。拟实施方案留在设计或计划中并标明状态，当前使用说明描述已交付行为。

<a id="know-04"></a>
## KNOW-04 自然表达

用完整句子说明对象、动作、依据和结果，标题直接说明问题。禁止自造压缩黑话、电报体、装饰性引号与加粗、模板式对仗，以及完整结论后的无信息免责。

不要先虚构一个错误观点，再用“不是……而是……”突出结论。删除后事实、范围和理解无损的否定必须删除。重要条件进入对应主张，完整解释进入句子；括号保留简称、单位和简短次要补充。

表格用于行列语义一致的检索或比较，长论证使用段落。注释解释非显然理由；正文和日志各自承担实际信息任务。

<a id="know-05"></a>
## KNOW-05 经验沉淀

将能改变未来决策的观察保存到已有责任文件，保留具体失败、触发条件、处理方法和有效验证。一次严重事故也可能值得记录；临时执行过程留在任务或工具记录。

同一问题优先修当前规则或方法、删除矛盾与重复，并为可观察行为补适当测试。避免每次事故都新增政策、门禁或复杂台账。旧状态和旧裁决在重新评估任务中的用法见 [ENG-05](engineering.md#eng-05)。
