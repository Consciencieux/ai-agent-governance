# 变更完整性

<a id="chg-01"></a>
## CHG-01 影响范围

从修改对象及邻近内容开始读取。局部文案、私有实现和公开接口采用与影响相称的调查范围；涉及调用关系、导出、注册、配置或共享行为时，再按这些线索展开搜索。停止条件是已识别并处理本次影响链。

用户点名的位置用于定位，明确限定的编辑范围用于授权。发现范围外的同类问题应记录具体位置与影响，继续完成获准部分。重命名、移动或拆分时，核对实际相关的扫描根、导出、测试发现、CI 和打包清单，防止机制继续只处理旧集合。

<a id="chg-02"></a>
## CHG-02 根因与同类实例

修复决定错误行为的条件或数据关系，检查共享同一约定的其他入口。依据行为和来源关系找同类实例，必要时扩展字符串搜索。

例如单条与批量入口使用相同的到期规则，要同时检查相等边界。生成或分发问题沿“来源 → 生成 → 消费者”核对有关层，修正来源并生成当前产物；相同契约的多个输出使用同一组契约样例核验。

<a id="chg-03"></a>
## CHG-03 完整删除

移除功能、概念或旧方案时，在授权范围检查名称、别名、文件名、实现、注释、配置、测试、示例、提示词、说明和生成物。补查动态调用、注册、环境变量及间接指代。

删除失效内容，重组受影响实现与句段，清理空标题、悬空引用和失效产物。禁止在当前说明中用“A 已移除”“不再使用 A”“A 已被 B 替代”等文字代替真正清理。

修改后在相同范围复查，运行保留行为及相关构建。真实发布历史、有效迁移说明、用户要求的记录和有消费者的兼容行为各留在其正确位置。搜索操作见[工具使用](../tools.md#search)。

<a id="chg-04"></a>
## CHG-04 兼容与持久数据

确定真实消费者、已承诺接口、部署方式和已有数据。内部重组或明确允许破坏兼容的任务直接采用目标设计，清除无用途的别名、双轨实现与迁移外壳。

已有消费者、数据库、配置或持久格式确需过渡时，明确转换、发布顺序、验证和失败恢复。滚动部署与数据迁移可需要阶段性兼容，即使接口只在项目内部使用。优先复用现有迁移设施；授权范围见 [PERM-02](permissions.md#perm-02)。

<a id="chg-05"></a>
## CHG-05 完成范围

按目标和完整差异核对本次已知问题。持续工作沿用一个计划、Issue 或任务记录，保留新发现问题的处置：已解决、范围外、待输入或明确后继。依次完成本次任务，避免追着新发现问题不断离开原目标。

预先列出的文件随实际依赖更新；计划与差异不一致时判断原因。禁止为了凑齐文件表制造修改、降低仍有效的断言，或只改变展示输出来掩盖失败。工作区与协作保护见 [PERM-02](permissions.md#perm-02)。
