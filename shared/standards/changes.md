# 变更完整性

<a id="chg-01"></a>
## CHG-01 影响范围

修改前读取对象的定义、调用与现有约定。按名称、别名、导出、注册点、配置键和相关行为搜索源码、测试及说明。受影响范围由实际依赖决定，用户点名的位置是起点。

重命名、目录移动或拆分后，检查扫描根、硬编码清单、CI 路径、测试发现规则、导出入口和打包清单。声明的对象集合与实现实际处理的集合逐项对应。

<a id="chg-02"></a>
## CHG-02 根因与同类实例

修复决定行为的原因，搜索共享同一约定的其他实例。格式、模板、生成或分发问题沿“来源 → 生成 → 消费者”回查相关层，更新产生错误的来源及其测试。

例如两种导入器采用相同的过期判断，只改报错的入口会留下另一处缺陷；模板和导出文件不一致时，应修模板并重新生成。同类搜索的依据是行为与来源关系，而非只查相同字符串。

<a id="chg-03"></a>
## CHG-03 完整删除

用户要求移除功能、概念或旧方案时，在授权范围检查名称与别名、文件名、实现、注释、配置、测试、示例、提示词、文档和相关生成物。读取动态调用、注册表、环境变量及“上述模块”等间接指代。

删除或重组有关内容，清理空标题、悬空引用、失效测试和遗留生成数据。当前说明直接描述保留的行为。禁止用“A 已移除”“不再使用 A”“A 已被 B 替代”“不要使用 A”等否定式说明代替删除。

完成后在相同范围重新搜索，并检查图件、生成产物与受影响的句段、链接和构建。项目既有发布历史、用户明确要求保留的记录及真实兼容用途按其职责保留；其余残留应清理。搜索命令见[工具使用](../tools.md#search)。

<a id="chg-04"></a>
## CHG-04 兼容与持久数据

先确定真实消费者、已承诺接口和已有数据。内部重构及明确允许破坏兼容的任务直接采用目标设计；禁止主动增加兼容别名、迁移系统或双轨实现。

存在真实外部消费者或持久数据义务时，明确新旧格式、转换顺序、验证与恢复方式，再完成所需过渡。破坏性操作的授权见[PERM-02](permissions.md#perm-02)。

<a id="chg-05"></a>
## CHG-05 完成范围

核对工作差异、已知问题和请求目标。每个本次必须解决的问题有明确结果；确需推迟的事项注明影响及具体后继位置。持续任务沿用一个工作记录，不另建平行台账。

禁止通过降低断言、跳过失败路径或只修改展示输出来清空问题。已有未提交工作与其他 Agent 的改动保持独立，发生同处变更时先核对再编辑。
