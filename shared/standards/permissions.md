# 授权与 Git

<a id="perm-01"></a>
## PERM-01 按请求确定权限

以用户请求、项目有效约定和宿主权限共同确定范围。实施请求包括完成该目标必要的代码、测试和相关文档修改；明确要求重构或删除时，按授权执行相应修改。只读审查和仅设计请求保持只读。

影响原请求之外的公开契约、数据、费用、许可、部署或权限时，先提出具体待决定事项。文件数量本身不触发确认。同一范围已经明确授权，直接执行，不重复询问。

<a id="perm-02"></a>
## PERM-02 工作区与破坏性动作

编辑前检查当前工作区，保留已有未提交和未跟踪内容。禁止为获得干净状态执行 reset、clean 或丢弃用户工作。普通源文件删除按开发授权处理；清空数据、覆盖外部环境、改写已共享历史等操作需要对应授权。

对授权含义或目标确有歧义时，明确指出将影响的对象再询问。已经请求的代码删除不自动扩展为删除数据、发布记录或仓库历史。

<a id="perm-03"></a>
## PERM-03 提交、推送与分支

读取 status、diff、log；暂存前确定属于本次的文件与改动块。用户要求“提交这些改动／提交一下”时，可提交当前已明确的变更集；推送、开 PR、合并和发布按对应请求或项目明确授权执行。“实现功能”本身不授权远端写入。

一次授权覆盖所述连续步骤，例如“提交并推送”包括必要的暂存、提交和推送。变更集、分支或目标发生实质变化时重新核对。项目分支保护和分支约定优先；没有相应要求时沿用当前分支。

提交前检查 staged diff、密钥与项目规定的验证。身份缺失请用户提供，不自行设置他人身份。推送冲突时说明分歧；禁止自行强推或改写共享历史。

<a id="perm-04"></a>
## PERM-04 发布与失败恢复

明确的发布请求授权其说明的版本、目标和常规发布步骤。先确认这些字段及产物可由现有项目确定，再进入发布工作流；尚未确定的目标或破坏性操作集中询问一次。

普通可恢复执行错误在原授权内定位和重试；恢复需要改变历史、扩大数据影响或改变远端目标时停下确认。结果按实际执行阶段报告。
