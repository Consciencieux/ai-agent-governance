# 授权与 Git

<a id="perm-01"></a>
## PERM-01 请求与权限

以用户请求、项目有效约定和宿主权限确定范围。实施包括完成目标必要的代码、测试和说明；授权重构或删除时直接处理相应源码。仅设计和只读审查按其产物结束。

常规依赖调整与本地开发步骤按任务授权进行。影响原请求之外的数据、公共契约、费用、许可、部署或权限时，集中提出具体待决定事项。同一范围已经获准，直接执行。

<a id="perm-02"></a>
## PERM-02 保护工作与数据

编辑前查看当前差异，区分本次改动、用户已有工作和并行修改。保留未提交及未跟踪内容；禁止用 reset、clean 或覆盖文件清空不属于本次的工作。操作同处内容时先核对，再做有针对性的编辑。

源文件删除按开发授权处理。永久数据删除、覆盖外部环境和改写他人已使用的历史，需要相应授权及保护措施。已有用户工作妨碍验证时可使用独立副本或 worktree；不要为方便操作擅自移动、暂存或回滚用户改动。

<a id="perm-03"></a>
## PERM-03 分支与提交

分支和提交方式沿用项目约定与当前任务。用户要求“提交一下”且变更集明确时完成提交；提交、推送、PR、合并按请求或项目已有授权执行。一次“提交并推送”覆盖必要连续步骤，实施请求本身不包含远端发布。

暂存前核对改动；所有变化都属于本次时可使用 `git add -A`，混有其他工作时按路径或改动块暂存。提交前回看 staged diff，使用项目规定的验证与密钥检查；身份缺失时请用户提供。

创建本地工作分支、整理本次未共享提交、amend 或 rebase 可以是授权工作流的正常步骤。以是否丢弃他人工作、改写已共享历史和改变远端为准判断风险，不能只按命令名称一律阻断。未经相应授权禁止强推、改写共享历史或额外开 PR。

<a id="perm-04"></a>
## PERM-04 发布与恢复

明确发布请求覆盖其确定的版本、目标和常规步骤；能从现有项目确定的信息直接核对，真正未决的范围集中询问。准备说明或评估发布条件以所需材料交付。

失败后先看当前状态。语法错误、暂时网络失败或本次代码问题可在原授权内修复并重试；推送分歧按项目工作流检查；只需快进或重放本次未共享提交时按既定流程继续，未知冲突或共享历史改写再提出具体决定。恢复需要扩大数据影响、改变目标或越权写入时停下确认。
