# 发布方法

## 准备实际版本

根据用户请求和项目版本约定确定发布类型、版本与目标。读取现有版本来源、已完成变化、发布工作流和分发方式。识别真正的兼容变化，整理使用者能理解的发行说明。

版本字段从实际维护关系同步；发行说明记录新能力、修复、变化及必要的使用影响。测试日志留在验证结果中。

## 验证与授权

检查实际要发布的源码与工作区，构建产物并在干净消费者环境中使用。按项目要求完成测试、密钥检查和重要平台验证。

“准备发行说明／评估能否发布”以材料交付结束；明确发布请求按授权标准确认版本、目的地及所含步骤。待确定的范围集中询问，已授权的常规步骤连续执行。

## 执行

使用项目现有发布工具或平台工作流，完成所需提交、标签、推送和发布。标签自动构建的项目等待相应运行，再核对上传资产；不要并行走另一条手工发布路径。

发布内容应对应已验证版本。HEAD、工作区或目标实质变化时，重新检查受影响部分。失败后按实际阶段恢复：远端已有标签或 release 时先查看现状，再补本次缺少的动作；不覆盖不匹配的版本或资产。

最后交付版本、目标链接、实际资产和发布状态。发布完成后结束。
