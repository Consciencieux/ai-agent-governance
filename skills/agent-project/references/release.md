# 发布方法

## 确定交付

读取用户请求、版本来源、已完成变化和项目发布方式。沿用版本策略，判断真实兼容变化；发行说明按 [KNOW-03](../../../shared/standards/knowledge.md#know-03) 记录值得说明的变化。

准备说明或评估发布条件时交付材料。实际发布按 [PERM-04](../../../shared/standards/permissions.md#perm-04) 核对版本、目标与常规步骤，未决范围集中询问。

## 验证版本

检查待发布的源码、工作区与产物归属，执行项目验证。相关安装或分发变化按 [VER-04](../../../shared/standards/verification.md#ver-04) 在消费者环境检查，复用同版本已有结果。

## 执行与恢复

使用项目现有工具，完成需要的提交、标签、推送和发布。标签触发自动构建时观察该流水线，再核对实际资产与版本；采用一条确定的发布路径。

HEAD、目标或源码实质变化时重验有关部分。部分发布失败时先查看远端：相符的已完成步骤保留，补缺失步骤；存在同名但内容不符的版本或资产时，先明确修复处置再覆盖。

交付实际版本、链接、资产和状态，完成后结束。
