# 项目接入与治理巡检

## 确定实际入口

读取当前项目的指令文件、目录、包管理器、CI、测试和文档。确认用户使用的客户端，从安装后的 Skill 列表和文件位置核对可发现性。安装说明由本产品使用文档提供，项目路径使用实际安装位置。

普通开发可直接使用日常 Skill。用户要求持久接入时，将[项目指令片段](../../../assets/project-instructions.md)合并到该客户端实际加载的入口，例如 AGENTS.md 或 CLAUDE.md。保留项目特有要求，只补本次需要的路由和真实命令。

## 建立最小充分的项目知识

已有架构、用法和工作记录继续使用。确实缺少理解项目所需内容时，再建立相应说明。仓库指令以当前任务入口、测试构建命令、重要边界和来源定位为主。

是否设置 CI、密钥扫描、分支保护或多 Agent 协作，由项目需求和用户授权决定。使用平台已有机制；只安装本次选择的设施。

## 巡检与验证

沿实际使用路径核对：客户端发现技能、入口读取适用标准、开发命令存在、配置与当前实现一致、调用脚本可在目标项目运行。观察失败时回查来源、模板或配置负责人。

只读巡检给出位置、影响与建议；已授权修复时更新负责人及依赖，再执行相关命令。完成一次只读调用和一次临时副本内的开发任务，观察具体加载与结果。
