# 审查方法

## 取得实际对象

确定基线、工作区变化、相关需求和已知决定。改变的代码连同调用者、测试和配置阅读。全仓或逐行请求按实际范围完整读取，分批保存位置与关键判断；普通改动审查围绕影响面。

## 按问题选择检查

先判断行为和结构是否正确，再检查证据与维护关系。审查公共入口、状态变化、异常路径和数据含义；查重复实现、错误所有权、投机兼容、无用配置、层层回退及只修局部的补丁。

验证测试能否区分正确与错误行为，目录、枚举和分发是否覆盖真实集合。文档与实现冲突时回查原始需求和实际运行结果，确定正确来源。

安全、性能、可访问性或特定平台问题在本次对象涉及时检查。按实际任务选择专业资料或独立协作，不固定派出若干子 Agent。

## 核实候选

对候选追到可说明的输入、条件或依赖。优先使用现有测试和临时隔离实验；验证结果关联到具体主张。正确的错误处理、必要架构边界和真实兼容行为保持其作用。

一次审查不以问题数量为目标。结构性问题先给整体处置，避免让几十条行级修补掩盖同一根因。

## 报告

先给结论与重要问题，再列准确位置、依据和处理方案。能够成立的结论直接表达；尚缺的关键输入写在受影响的判断处。只读范围内保存报告仅在用户要求报告文件时执行。
