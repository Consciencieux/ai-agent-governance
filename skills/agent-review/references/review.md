# 审查方法

## 取得实际对象

确定需求、基线、当前差异和有关决定。改动审查读取变化及其调用者、测试和配置；全仓请求按实际源码范围通读，逐行请求按指定深度展开。用 [Git 状态与差异](../../../shared/tools.md#git-diff) 区分新增、修改、删除和重命名。

## 判断当前设计

先判断行为与职责是否符合目标，再检查实现、测试和文档。重新评估时检验旧决定的前提；当前结构失配时比较整体替换、重组或删除，不把问题全部拆成行级补丁。

检查相关输入、状态变化、资源和错误路径。安全、性能、平台与可访问性在对象涉及这些要求时加入；按需要使用专业工具或独立协作。

## 核实与报告

候选问题追到具体输入、条件和实际影响。已有结果能回答问题时复用；需要实验时选能区分正确与错误的测试。保留有用途的错误处理、边界、配置与兼容行为。

报告以结论和重要问题开头，提供准确位置、依据与明确处置。不存在实质问题时直接说明。只在用户要求文件时保存报告；仅分析报告的任务不改被审查内容。
