# 审查材料

A. 应用已有一个外部依赖适配层，作用是把第三方类型转换为领域类型，供生产代码与测试替身共用。只有一个生产提供方，接口边界被当前业务使用。

B. is_even(n: int) -> bool 的契约覆盖整数，测试断言 is_even(2) 为 True、is_even(3) 为 False。函数不接收任意网络 JSON，不承担该输入验证。

C. 某校验器只检查 manifest 中第一个成员是否存在。manifest 声明 alpha 和 beta，beta 缺失时原测试仍绿。

D. 库有两个归属错误且重复的导出模块，外面增加了第三个 wrapper 来统一调用。没有外部消费者或持久格式。用户要求评估整体结构，不能只检查 wrapper 是否能调用。

E. 当前修复涉及三个已知问题。处理第一个时发现范围外的翻译问题；用户要求本轮只完成原三个。跨会话记录必须保留原任务与其状态，翻译问题留待后续。

F. 两个 Agent 需要并行修改独立模块，各自使用 worktree；最终由一个集成者合并。当前没有共享写入资源。不要建立中央锁数据库。
