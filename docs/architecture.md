# 架构

## 执行路径

主入口 `SKILL.md` 是 `ai-agent-governance` 的日常开发工作流，直接处理用户的实现、修复和重构。独立审查使用 `agent-review`，项目接入和发布使用 `agent-project`。同一个 Agent 可按请求顺序执行这些角色。

日常路径：取得目标与代码 → 读取本次适用标准 → 决定并实施 → 验证受影响行为 → 交付。

## 责任归属

核心集中在 shared/core.md。六类标准分别负责工程判断、变更完整性、验证、知识维护、授权和安全。各主题保存独立判定、典型错误及必要例外。方法保存设计、实现、诊断、重组、审查、接入和发布的操作。

每个入口定义自己的加载表。动作条件按并集处理，方法和标准直接从入口可达；新增动作在执行前补读。上下文恢复和多 Agent 交接统一由 shared/context.md 负责。

日常实施读取工程、变更和验证标准，文档、Git 与安全专题在相关动作发生时加入。核心和已读取的未变更材料在同一会话复用。

## 产物与工具

目标项目继续使用自己的指令、命令、测试、文档和平台能力。工具方法集中在 shared/tools.md。源代码仓库只提供打包器；执行角色使用现有搜索、Git、构建、扫描及宿主工具。

构建将 shared、assets 和各角色的方法复制进对应技能目录，再改写相对链接。三个目录共同形成可安装的套件；跨角色链接指向相邻技能入口。维护文档、测试和评估材料保留在源码中。

## 验证

单元测试检查源文件、链接、标准引用和实际安装包。固定行为用例覆盖任务触发、加载、实现与审查结果。运行时保存真实输出、改动、加载记录和用户需要纠正的事项，结果用于下一轮修订。
