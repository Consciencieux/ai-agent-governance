# 架构

## 三个直接入口

`ai-agent-governance` 完成日常实现、诊断、重构和文档任务；`agent-review` 交付独立只读判断；`agent-project` 承担明确请求的接入、CI 和发布。角色按用户要的产物选择，同一 Agent 可依请求顺序继续。

## 规则与方法

核心保存少量关键行为。工程、变更、验证、知识、授权、安全六份标准各自维护判断；方法提供设计、实施、诊断、重组、审查与项目工作流的做法。标准保留稳定 ID 和 HTML 锚点，跨文件直接链接。

每个执行入口维护自己的任务加载表，条件取并集。整文件链接读取全文；章节链接读取完整规则；重点锚点用于在已读标准中定位。纯文案使用核心和知识标准，代码任务再加载工程、变更与验证。新操作补读，恢复和来源变化按 shared/context.md 处理。

## 分发

源码中的共享规则只有一份。构建器把各角色需要的方法、shared 和 assets 放入对应 Skill，重写相对链接并核验文件与锚点。三个目录放在同一个宿主 Skills 根下，角色之间链接到相邻入口。

维护文档、测试与离线评估保留在源码。安装后的技能使用目标项目命令、宿主能力和实际平台保护。

## 验证

[行为评估](../evals/README.md)记录实际产物、读取路径、额外工作、人工纠正与成本。单元测试验证具体资源关系和功能判定器，真实客户端任务用于观察规则执行效果。
