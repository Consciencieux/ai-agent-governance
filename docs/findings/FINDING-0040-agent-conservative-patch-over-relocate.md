# FINDING-0040：Agent 改仓库偏保守——宁可原地打补丁堆成屎山，也不敢搬家或删除

## 分类

- 严重度：高（局部绿、整体腐；与「精致的狗屎」同族）
- 影响范围：repo 施工 Agent · skill 入口/政策编辑 · 脚本与文档生命周期
- 研究方向：G. 证据 / 研究方法 · C. 执行缺口 · G05 治理自身膨胀

## 观察

对「入口太厚 / 脚本是屎山 / 该不该删」一类任务，Agent 的默认姿态是：

1. **先默认现存物有用**——除非别处已经有一份几乎相同的正文，否则不敢删、不敢搬。
2. **优先原地补丁**——在现有文件里加指针、加一段、削一句；把「重构权威落点」当成高风险越权。
3. **把克制误读成保留**——`coding.policy` 的工程克制本意是少造无用机制；被执行成「少动已有机制」，于是屎山获得永久居留权。

这与「用户要瘦 SKILL」时的实际行为一致：只删**已证明重复**的段落；策略层、编排层因为「policy 里还没有同名专章」就被留在入口。用户指出后才改为**先新建 `runtime-invariants.policy` / `skill-execution` 再搬迁**——正确顺序是搬家，不是「有重复才敢删」。

同姿态曾出现在脚本面：面对明显臃肿的 Gen1 CLI / 检查器堆，倾向论证「可能还有用 / retire 必须为空 / 今日不删」，而不是先定 disposition 再隔离。FINDING-0028 关掉了「身份未登记」半截，但 **`retire = ∅` 被当成「都不能动」的心理许可**，与本条同轴。

## 证据

### A. 本轮（2026-09-16）SKILL 瘦身

| 做法 | 结果 |
| --- | --- |
| 第一刀：删概念图、Git 复述、Phase 百科；策略层仍留在 SKILL | 入口仍啰嗦；「单一事实源」等无专属 policy 家 |
| 用户纠正：应搬家，不是只删重复 | 才新建 `runtime-invariants.policy.md` + `skill-execution.md`，SKILL → ~53 行路由 |
| 对照 | policies 里原先只有局部「单一事实源」用语，没有 skill/运行期契约专章——按「有重复才删」会永远留在入口 |

### C. 训练与激励偏见（可观察行为，非道德指责）

- 改坏权威 / 删错脚本的惩罚，在对话里远高于「多留一坨」的惩罚。
- 「完整 = 负责」「最小 diff = 安全」在补丁文化里被奖励；「先立权威再搬迁」步骤多、看起来像扩大 scope。
- 工程克制写了「已批准需求优先 / 不擅自删需求」，被泛化成「不擅自删任何现存文件」。

## 根因

**不对称的风险模型：** Agent 把「删除/搬家」当成可能越权的破坏性动作，把「追加补丁」当成可逆的安全动作；又缺少强制的**变更归位检查**（权威应在哪 → 是否仍在错误层 → 必须迁走）。于是系统收敛到局部最优：门禁可绿、文件越来越多、入口与脚本越来越厚。

这不是单纯「懒」，而是 **FINDING-0014 局部优化 + FINDING-0015 存在感补偿 + FINDING-0032 不敢动结构** 在编辑策略上的合流。

## 影响

- 薄入口 / ADR-0022 无法落地：入口永远等「别处先有一份」才肯瘦。
- 脚本与文档屎山自我辩护：「还在用 / 登记为 keep / 不敢 retire」。
- 用户反复同一纠正（搬家、删空壳、别保守），注意力浪费在元过程而非产品。
- 与「精致的狗屎」（0014）闭环：补丁越多，越不敢动，越需要更多补丁。

## 关闭条件

1. **编辑启发式成文（INSTALLED 或本仓施工纪律，一处权威）：** 当任务是「入口/政策过厚」或「疑似屎山」时，默认流程是 **定权威落点 → 搬家或删除 → 改指针**；禁止以「目标位置尚无同名正文」为唯一理由保留错误层上的全文。
2. **与工程克制对称：** 克制「擅自新增机制」的同时，显式允许并要求「已判定错位/零增量时的迁删」；不得把克制读成保留义务。
3. **至少一次对照案例入库：** SKILL → `runtime-invariants` + `skill-execution` 可作为正例；再选一类脚本或文档屎山走完 disposition → 迁/删 → 指针闭合（可与非空 `retire` 切片合并，但不阻塞本条成文）。
4. **本条不替代** 0014/0015/0032/0028 各自关闭条件；那些关闭后，本条仍须证明「搬家优先」启发式已写进可引用纪律，而不仅是一次会话纠正。
