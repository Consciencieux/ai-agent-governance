# FINDING-0036：Agent 爱造压缩黑话标题，读者读不懂却当「精确」

## 分类

- 严重度：中（知识对象与 Finding/Plan 标题是给人读的；黑话降低审查与交接效率，并伪装成已想清楚）
- 影响范围：本仓建设文档（`docs/findings/`、`docs/plans/`、ADR/研究叙述、Agent 对话摘要）；非 skill 运行时行为
- 研究方向：G. 证据 / 研究方法 · G05 治理自身膨胀；与语言政策「用简体中文」正交——**用了中文≠可读**
- 同族：FINDING-0031（用权威口吻冒充判断）；FINDING-0034/0035（把难问题说成好听的机制名）

## 观察

Agent 写 Finding / 盘点标题时，常把一句普通中文压成**四字/六字复合黑话**（或中英夹生标签），听起来像研究结论，实际上是自造词。读者要二次翻译才能懂；作者（含后续 Agent）却把它当已固化的精确概念继续引用。

**不是**为了故意让人看不懂；动机通常是：压缩字数、显得「像治理论文」、把英文 compound（mechanical theater / low-ROI cluster）硬译成汉字串。效果与故意晦涩相同。

## 证据

1. FINDING-0035 原标题「难语义贴机械皮」——维护者当场问「这是中文吗」；本意只是「难判定的语义外面糊一层假门禁」。
2. FINDING-0034 标题残留「难问题机械皮」——同一压缩病。
3. 对话与 CHANGELOG 英文侧也堆 `mechanical-theater`、`vacuous pass`、`QUESTIONABLE` 等内部标签，中文正文若只贴标签不解释，读者同样迷路。
4. 现有语言政策只规定 findings **用简体中文、不进三语树**，**不**约束「标题必须让未读完全文的人一眼懂」。

## 根因

1. **压缩崇拜**：把短标签当成可复用术语，未先写一句人话定义。
2. **英译硬贴**：英文研究黑话直译成汉字串，语法像中文、语义像内部代号。
3. **精确错觉**：造词成功 → 误以为问题已被命名并理解；审查成本转嫁给读者。
4. **无刹车**：没有「标题可读性」审查项；门禁只扫结构/ID，不扫是否像人话。

## 影响

- Finding 索引与导航变成黑话词典，新人与跨会话 Agent 都要猜。
- 与「记录 Finding 是为了可复查」目标相反：记录了，但读不通。
- 易与真机制名（CTRL-、cluster 文件名）混淆——文件名可保留英文代号，**中文 H1 不行。**

## 关闭条件

1. 本仓约定写入 `docs/findings/README.md` § 语言政策：中文标题必须人话可读；禁止自造复合黑话；不新增机械禁词门禁。
2. 已知病例改名：FINDING-0034 / 0035 的 H1 改为白话。
3. 后续靠对话/审查纠正；不得靠再造更短黑话或「禁黑话」门禁「修复」。
