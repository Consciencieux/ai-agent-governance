# Governance Capabilities Overview

[English](overview.md) · [简体中文](../zh-CN/overview.md) · [繁體中文](../zh-TW/overview.md)

## What This Is

`ai-agent-governance` is an installable AI Agent Skill. It writes a governance framework into the target repository — rules, validators, drift detection, release controls — so that constraints survive across agent sessions rather than vanishing with chat context.

Tool-neutral: works with Claude Code, Cursor, opencode, Codex, and others.

## How It Lands

Governance is not a single file. Each concern has up to three layers, loaded on demand:

```
Policy (read)           Script (run)          Task card (do)
docs/rules/*.md      →  scripts/*.js       →  docs/rules/capabilities/*.md
always-on rule text      mechanical gate/report   leaf exists only when task has steps
```

- **Policies** (`docs/rules/*.md`) — always-on rules read by agents and humans. INIT copies them from the skill's `references/policies/`.
- **Scripts** (`scripts/*.js`) — zero-dependency Node gates run by CI or agents; exit code is the evidence. INIT copies them from the skill's `scripts/`.
- **Capability leaves** (`docs/rules/capabilities/*.md`) — present only when a task has distinct steps (e.g. deterministic init, release orchestration, audit drift). Not a feature directory — concerns covered by policies and scripts may have no same-named leaf.
- **Generated sub-skills** (`.governance/generated/skills/`) — agent modules generated by INIT for day-to-day tasks (drift patrol, validation, release, state recording, etc.).

### Entry-point priority

| Who | Entry path |
| --- | --- |
| Governed-project agent | `AGENTS.md` (auto-loaded) → `docs/rules/` → generated sub-skills |
| Developer | `scripts/` CLI · `docs/rules/` rules · `.governance/` state files |
| Skill executor | `SKILL.md` routing table (read / run columns) |
